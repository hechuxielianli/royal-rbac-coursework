# 库滕堡皇家铸币厂与市政厅政令系统

软件系统分析与设计 · 第三次作业。基于 **Flask + SQLite + 原生 JavaScript**，以《天国：拯救 II》的银城与铸币厂为灵感，将原创教学业务与 RBAC 访问控制、同步事件监听机制结合，核心页面资源随源码提供，支持本地运行与数据持久化。

## 运行

需要 Python 3.10 或更新版本。在 Windows 中双击 **start.bat**，等待首次依赖安装后访问 **http://127.0.0.1:5000**。也可在本目录执行：

```powershell
.\start.ps1
# 端口被占用时
.\start.ps1 -Port 5050
```

通用命令：

```text
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python run.py
```

macOS / Linux 使用 `.venv/bin/python` 代替 `.venv\Scripts\python`。运行后端不需要 Node、数据库服务器或前端构建工具。首次安装 Python 包需要网络；脚本与应用样式均从本地加载。Google Fonts 仅提供可选展示字体，字体服务不可用时使用本机后备字体；依赖安装完成后，登录、受控页面、权限配置及业务操作均可离线运行。

人物与职务分配采用原创教学设定，汉斯扮演铸币司库并非游戏剧情官职。场景来源、实际业务及边界见[库滕堡场景说明](docs/kuttenberg-scenario.md)。格罗申是模拟账目单位，初始余额为3200，页面显示数据库实际余额。

当前前端采用黑曜石与暗金典藏主题：身份/领地、业务台、事件终端构成桌面三栏，卷轴正文采用暖色羊皮纸；真实拒绝反馈和三态日志时间轴保留服务端裁决依据。设计边界及补充视觉检查见[界面重构说明](docs/ui-redesign.md)。

## 数据与边界

- `instance/` 存放首次启动生成的 SQLite 数据库与会话密钥，重启不会清表。备份时先停止程序，再完整复制该目录。
- 首次登录默认激活所有直接角色，可在界面主动收缩激活范围；新增分配角色需自行激活或重新登录。撤销的角色与权限在下一次请求立即失效。
- 无权菜单默认隐藏；无权按钮禁用。界面另设明确的越权测试入口，帮助观察真实服务端 403 拒绝。
- 菜单、页面与操作是独立权限。拥有菜单不自动获得其页面或操作，拥有页面也不自动获得按钮权限。
- RBAC2 实现静态职责分离 SSD，未实现 DSD、角色基数或先决条件约束；本项目是 RBAC96 模型族的教学实现，不声明标准认证。
- 用户角色分配、角色权限矩阵和继承边支持在线编辑；角色/权限目录与互斥规则持久化，但不提供其在线新增删除或互斥规则编辑界面。完整管理员可以向他人委派合法业务角色，部分管理员受修改前的权限范围约束；不实现完整ARBAC或双人审批。
- 三类策略PUT必须携带管理快照的`base_revision`，旧版本返回409 `STALE_POLICY`，界面保留候选并提示重载。所有用户均不能修改自己的直接角色分配。
- 事件终端显示当前权限范围内最近40条记录，可手动刷新；不是跨浏览器实时推送。会话恢复不会自动重放业务写请求。当前接口没有请求幂等键，每次显式提交代表一次政令。
- 本地教学程序使用公开演示密码，只监听 `127.0.0.1`，不应直接用于真实系统或公网服务。审计持久化可用于演示，数据库管理员仍能修改本地 SQLite 文件。
