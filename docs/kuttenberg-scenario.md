# 库滕贝格皇家铸币厂与市政厅政令系统

本项目以《天国：拯救 II》的波希米亚、库滕贝格和特罗斯基为灵感，设计原创的RBAC教学业务。游戏角色作为演示账号，具体职务、军队编制、护送路线、税率、角色继承和反走私法令均为课程模型。汉斯在此扮演铸币司库，不表示游戏中实际担任该职；阿格尼丝为本项目教学人物。没有将奥托与拉德季的政治身份合并，也没有新增名为瓦瓦克的虚假业务账号。

## 场景依据

- [发行商PLAION发布稿](https://press.plaion.com/es/THE-WAIT-IS-OVER-KINGDOM-COME-DELIVERANCE-II-IS-HERE)介绍游戏位于1403年的波希米亚；[游戏官方网站](https://www.deepsilver.com/games/kingdom-come-deliverance-ii)介绍亨利与库滕贝格的铁匠场景。
- [意大利宫运营方](https://pskh.cz/en/italian-court/)说明建筑曾为皇家铸币厂与宫殿，并介绍布拉格格罗申。本项目借用这些场景及货币名称，不据此推断1403年真实行政系统、历史税率或汇率。
- [官方1.4更新说明](https://www.deepsilver.com/gb/games/kingdom-come-deliverance-ii/news/patch-14)分别提及特罗斯基城堡和Via Argentum任务。银矿走私情节可启发职责分离案例，但“走私案由缺少RBAC2导致”是现代工程类比，不能作为剧情或历史上的已证实因果结论。

核对日期：2026-10-23。界面盾徽为项目原创SVG双尾银狮，未复制游戏纹理、截图、标志或原生界面资产。

## RBAC0—3的教学关系

RBAC0以用户、角色、权限及会话为基础；RBAC1允许卫队长、司库和审计官继承行会角色权限，国王继承军事角色权限。继承关系是显式政策，不按人物爵位或声望自动判断，更不表示真实社会中贵族天然掌握所有行会技能。

RBAC2采用静态职责分离：同一用户的已授权角色闭包不能同时包含`TREASURER`与`AUDITOR`。另有拨款与审计权限冲突检查，避免把两项权限直接塞入其他角色而绕过分离。角色分配、权限矩阵和继承变更都接受校验，冲突返回409并回滚。界面的“皇家反走私法令”展示来自真实拒绝响应，不产生模拟通缉记录或声望分数。RBAC3将继承与约束组合，国王同样受约束；本项目没有实现DSD或同一单据的双人审批。

## 数据兼容与反馈

`gold`、`opening_gold`等既有字段及全部路由、角色码、权限码和ID保持不变；格罗申是教学记账单位，不执行金银兑换。余额直接来自SQLite；首次装载显示实际值，变动时立即更新数字并短暂显示真实差额。减少动态效果偏好下保留数字和差额，关闭滚动与闪动。

展示迁移使用独立`theme_meta`版本，核心数据版本仍为2。迁移只替换已发布的默认标签和正文，逐字段保留自定义内容；不重放种子授权、不变更策略版本，不重写旧业务描述、余额、流水或审计记录。历史记录可能保留旧版“金币”措辞，以保持原始证据。授权、拒绝、事务和管理范围仍由原有服务端监听链执行。
