# 课堂演示指南（约 7 分钟）

## 演示前准备

按 README 启动应用，在浏览器打开本机地址。确认数据库为初始种子或已恢复到下述矩阵，避免上次修改影响预期。所有账号密码均为 `Kingdom@2026`：`henry` 平民、`radzig` 卫队长、`hans` 铸币司库、`wenceslas` 国王、`agnes` 审计官。

演示中同时观察当前身份/激活角色、业务计数和事件终端。先记下铁剑、出征、格罗申和审计的当前值，不要求它们固定为某个初始数值。权限冲突演示不应改变已保存政策；临时增加的权限在最后恢复。

## 1. 平民视角与真实页面拦截（约 60 秒）

以 `henry` 登录。说明登录识别“谁在操作”，角色和权限决定“可以做什么”。初始平民只有公共广场入口、赋税告示与铸剑权限；未授权入口隐藏或锁定。

打开市政税务告示，观察 `PAGE` 授权成功事件。再在地址栏直接访问：

```text
http://127.0.0.1:5000/pages/defense_map
```

预期：返回 **403** 拒绝页面，没有边疆布防正文。打开开发者工具 Network 可看到真实状态码。使用实际启动端口；返回大厅后继续演示。

讲解：“菜单隐藏负责导航体验；直接输入地址仍由服务器检查页面权限。”

## 2. 业务写入与绕过按钮的 403（约 50 秒）

仍使用亨利，执行一次“打造铁剑”。预期铁剑数恰好增加 1，刷新后保留；事件显示允许、数据库提交与审计保存。

展开大厅下方“越权验证沙盘”，选择“签发运银护送调令”并点击“发送验证请求”，或使用下方附录中的控制台请求。预期 **403**，出征次数不变；事件目标是 `btn:deploy_cavalry`，原因是缺少权限。给请求加上假的 `user_id` 也不能变成国王。

讲解：“按钮禁用只是提示。即使手工请求写接口，服务端仍从当前会话识别亨利，拒绝时没有业务副作用。”

## 3. 国王继承而非自动全权（约 50 秒）

退出并以 `wenceslas` 登录。观察直接角色为国王，有效角色包含国王、卫队长、平民。打开边疆布防图并执行一次调遣骑兵，预期页面成功、出征次数增加 1。

国王可读取国库总账、查看管理界面和全体事件，但种子状态下**不能拨款，也不能执行账本审计**。尝试对应动作应得到 403，格罗申和审计次数保持不变。

讲解：“继承方向是国王 → 卫队长 → 平民；财政与审计角色不在这条继承链中。系统没有写死‘国王直接放行’。”

## 4. 会话角色激活（约 40 秒）

在左侧身份区域展开“调整会话激活角色”，取消全部激活角色并点击“更新会话”。预期有效角色和权限为空，受控菜单及管理功能随之不可用，直接请求军事动作被拒绝。然后通过同一入口重新激活国王角色，权限恢复。

讲解：“激活角色必须是已分配角色的子集；停用是当前会话的最小权限选择，不是删除数据库中的角色分配。自助激活接口不要求管理员权限，因此可以恢复自己已获授的角色。”

## 5. SSD、继承冲突与原子回滚（约 75 秒）

国王点击“枢密院管理”，在“爵位册封”中选择亨利，记录其原有角色，提交同时包含“铸币司库”和“皇家银库审计官”的候选角色集。预期 **409** 职责冲突，原有角色完整保留。

再切换“继承关系”，保留原有四条边，并尝试同时增加：

```text
国王 → 铸币司库
国王 → 皇家银库审计官
```

预期 **409**，因为现有国王用户的有效角色闭包会同时包含互斥职责。重新读取继承关系，仍然是初始四条边，没有只保存一条的中间状态。

讲解：“SSD 不只比较直接册封。修改继承关系也可能间接形成冲突，因此要在事务中检查候选政策并整体回滚。”

册封者不能修改自己的直接角色分配。完整管理员可以给其他臣民授予合法财政或审计角色；只有部分管理权限者还受委派范围约束，不可借册封或改矩阵扩张管理能力。准备两份管理快照时，先保存的一份递增策略版本，旧版本提交应出现`STALE_POLICY`；先重新载入当前配置，再决定如何重填，不强行覆盖。

时间充裕时可再展示：加入“卫队长 → 国王”形成循环会被拒绝；向某个角色同时勾选“拨款”和“审计”也会因额外业务权限冲突而拒绝。后者独立于角色 SSD，防止用直接授权绕开职责划分。

## 6. 动态权限修改立即生效（约 60 秒）

在“枢密院管理 → 权限矩阵”选“行会平民”的直接权限，保留原有三项，只临时增加 `btn:deploy_cavalry`，保存成功。不要增加军事菜单或布防页面权限。

切换亨利，再用“越权验证沙盘”请求调遣骑兵。预期成功且出征次数增加 1；军事菜单和布防页面仍没有权限。可以在一个浏览器保持亨利、另一个浏览器保持国王，证明旧亨利会话也在下一次请求使用新授权，无需重新登录。沙盘会发出真实请求，有权动作会真实改变业务数据。

讲解：“谁拥有权限来自数据库。菜单、页面、动作是独立权限码，新增动作权限不会隐式放行页面。”

## 7. 重启与恢复现场（约 45 秒）

记下当前业务计数及刚增加的平民调遣权限。按 README 的方式停止并重新启动应用，刷新浏览器；必要时重新登录。预期业务计数、权限配置及审计历史保留，初始化没有重新播种覆盖。

最后以国王移除刚才给平民增加的 `btn:deploy_cavalry`，保存；亨利的下一次调遣请求再次返回 403。确认平民仍保留公共广场、赋税告示和铸剑三项原始权限。

## 可选：真实账本核对

用财政账号`hans`在皇家国库执行一次拨款，再切换审计账号`agnes`，进入国库执行独立审计。检查核对报告中的开账余额、格罗申流入/流出、预期余额、实际余额、差异及流水覆盖上界。正常情况下差异为0；审计计数增加只是成功保存报告的附带指标，不再代替核对本身。

差异场景由自动化测试在临时数据库修改实际余额后验证。课堂正常演示不直接修改运行数据库，以免破坏随后操作的基线。该核对没有外部凭证，不能证明同库账本和余额都未被篡改。

讲解：“重启不清空数据；撤权对下一次请求生效。演示结束时恢复原始授权边界。”

## 浏览器控制台：直接请求验证

当界面按钮已隐藏或禁用，可以使用浏览器开发者工具 Console 发起当前会话请求。此辅助方法用于说明后端边界，不需要修改页面 DOM，也不会改变当前身份。

```javascript
{
  const boot = await (await fetch('/api/bootstrap')).json();
  const response = await fetch('/api/actions/deploy_cavalry', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      'X-CSRF-Token': boot.csrf_token
    },
    body: JSON.stringify({user_id: 4})
  });
  console.log(response.status, await response.json());
}
```

亨利初始状态预期为 403；增加平民动作权限后预期为 200；撤销后恢复 403。`user_id: 4` 是故意添加的冒充参数，服务器不会把它当作操作者。更换登录身份后重新执行整段，避免使用旧 CSRF Token。

直接测试真实页面 API：

```javascript
{
  const response = await fetch('/api/pages/defense_map');
  console.log(response.status, await response.json());
}
```

外层花括号使示例可以在同一 Console 中重复执行。地址栏的 `/pages/defense_map` 是独立 HTML，`/api/pages/defense_map` 是 JSON，两者都由服务器鉴权。

## 可选补充验证

| 场景 | 操作与预期 |
| --- | --- |
| 财政业务 | `hans` 拨款一次，格罗申减少 100；审计动作 403 |
| 独立审计 | `agnes` 审计一次，审计数增加 1；拨款动作 403 |
| 管理越权 | 亨利直接读取 `/api/admin/state` 返回 403 |
| 审计范围 | 亨利只能读取自己的事件，国王可读取全体事件 |
| 非法激活 | 亨利尝试激活未分配的国王角色被拒绝 |
| 最后管理者 | 尝试移除最后一位完整管理员的必要管理权限，政策被拒绝且原配置保留 |
| 错误输入 | 非法角色 ID、重复 ID、错误 JSON 返回明确错误，不留下部分写入 |
| 未登录 | 退出后请求受控 API 返回 401；登录页和公共外壳仍可使用 |
