## 等价类和边界

采用弱健壮设计：除被考察字段外，登录身份、CSRF、路径及其他字段保持有效。

| 用例编号 | 输入分区或边界 | 预期 |
| --- | --- | --- |
| E01—E02 | 激活数组 `[]`、`[1]` | 200；分别激活空集与已分配角色 |
| E03—E04 | 未分配的已有ID、未知ID | 403 UNASSIGNED_ROLE |
| E05—E07 | 数组位置输入null、字符串、对象 | 400 |
| E08—E14 | 0、负数、小数、布尔、字符串、嵌套项、重复ID | 400 |
| E15—E17 | 数组长度5、100、101 | 前两者类型与长度检查通过、因含未分配ID403；101项越过长度上限400 |
| E18—E21 | 余额0、99、100、101，单次支出100 | 前两者409且不记账；后两者200，余额分别0、1 |
| E22—E29 | base_revision为null、布尔、0、负数、字符串、小数、当前1、未来2 | 前六类400；当前版本200并递增；未来版本409 |
| E30—E35 | JSON对象、根null/数组/字符串、语法损坏、错误媒体类型 | 仅JSON对象可执行；其他400且不改业务 |
| E36—E41 | 用户名80/81字符、口令200/201字符、非字符串账号/口令 | 长度上限内的未知凭据401；越界或类型不符400 |

每个拒绝用例比较 `kingdom_state`、`business_ledger`、`audit_report`、`policy_state`、`sys_user_role`、`sys_role_permission` 和 `sys_role_hierarchy` 的执行前后快照。审计表允许增加拒绝记录，所以未纳入“不变”快照。

## 随机性质

所有性质禁用持久化示例数据库与耗时截止，设置固定随机种子；JSON生成器覆盖null、布尔、整数、有限浮点数、Unicode字符串、数组及对象，递归树最多15个叶子。字符串显式排除Unicode代理项类别Cs，浮点数排除NaN与Infinity；这些畸形值由独立缺陷回归用例检查。实际生成例数从 pytest JSON 的 `user_properties` 中读取；其中 `http_operations` 只计各性质直接考察的操作请求，不计初始化登录和前后状态GET。

| 用例 | seed | max_examples | 不变量 |
| --- | --- | --- | --- |
| Q01 | 2026102801 | 300 | 激活输入必须为无重复、在1至2^63−1范围内的整数数组；仅已分配子集成功；拒绝保留原激活状态；业务和策略不变 |
| Q02 | 2026102802 | 300 | 仅正整数当前版本可保存；无效版本400、非当前版本409；拒绝保留全部业务和策略 |
| Q03 | 2026102803 | 300 | 业务动作只接受JSON对象根；其他根类型400；接受对象时只增加一把铁剑和一条流水 |
| Q04 | 2026102804 | 200 | 随机生成1—16步的五用户/四动作序列；状态变化符合固定权限表；余额=3200−真实支出；流水条数=成功动作数；审计差异为0 |

Q04的每个生成例开始前重置独立测试库的业务量与业务流水，五个客户端会话保留。序列最多16步、每次支出100，起始3200，因此该性质关注权限和记账，余额耗尽由E18—E21单独检验。一次pytest性质用例包含多个生成例，一份生成例也可含多个HTTP请求，这三个计数分别报告。

## 执行文件

运行命令：

```powershell
.venv\Scripts\python.exe -X utf8 -m pytest tests/test_function_spec.py tests/test_equivalence.py tests/test_random.py -q --json-report --json-report-file=evidence/new-tests.json --junitxml=evidence/new-tests.xml
```

首轮执行日志：`new-tests.log`；结构化结果：`new-tests.json`；JUnit记录：`new-tests.xml`。按修订后ID上限与JSON契约重新执行的结果保存为 `new-tests-after.log`、`new-tests-after.json`、`new-tests-after.xml`。结果数字以对应文件为准。

修订后运行结果为 **65项通过，耗时193.40秒**，其中功能/规格20项、等价类/边界41项、随机性质4项。Q01、Q02、Q03各实际执行300个生成例与300条受检操作；Q04实际执行200个生成例与1329条受检操作，合计 **1100个生成例、2229条受检操作请求**。首轮65项也全部通过，耗时130.58秒。两轮运行均有其他验证进程同时执行，报告分别记录运行耗时，不以两轮时长差推断软件性能变化。
